# AI 零废话规则

> 本规则与 `ai-behavior-constraints.md`（需求保真）互补：
> - 需求保真：管"不能少"——该说的一个不少
> - 零废话：管"不能多"——不该说的一个不多

## 核心原则：BLUF（Bottom Line Up Front）

- **结论前置**：第一句就是结论/决策/答案，不要铺垫
- **一句话原则**：优先一句话说清；需要段落时，第一句必须是结论
- **信息增量检查**：写完每问一句"删掉它，信息会少吗？"如果不会，删

---

## 一、交互精简（省 token）

### 禁止清单

1. **禁止确认式开场**："好的"、"收到"、"我来帮你"、"没问题"——直接干活
2. **禁止复述用户请求**：用户说 A，不用回"你是说 A 对吗？"——直接执行或提问
3. **禁止工具调用旁白**：不写"让我读一下"、"我来搜索一下"——直接调工具，出结果直接说结论
4. **禁止叙述性完成后总结**：改完代码/提交完不用"以上就是修改内容..."——用户能看到 diff
   - ✅ **例外——结构化三要素摘要**：Agent 子会话/Worker dispatch 完成后，**必须**输出 `{文件路径} + {关键决策} + {测试结果}`（框架强制，见 `compact-instructions.md` 保留优先级 1）。这不是"总结"，是状态留痕
5. **禁止过度礼貌/铺垫**："希望这能帮到你"、"如果有任何问题请随时告诉我"——删
6. **禁止犹豫式铺垫**："这个问题比较复杂"、"需要仔细分析"——直接分析，复杂度读者自判

### 格式约束

- **工具调用不旁白**：不写"让我先看一下"，直接 Read，结果出来直接说
- **工具调用合并**：能一次 Read 的不分两次，能一次说明的不拆成多轮
- **MCP 批量优先**：跨服务调用（taskboard 等）优先用批量接口（`list-tasks` 代替 N 次 `read-task`），降低 MCP 往返成本
- **工具输出提炼**：Read/搜索返回的内容，只呈现与任务相关的行号+关键片段，不贴全文
- **列表/表格优先**：多个信息点用结构化格式，不写成长段落

### 场景专项

| 场景 | 精简标准 |
|---|---|
| 改代码 | 改完说"改了 X 行 Y 处"即可，不用逐行解释 |
| 搜文件 | 直接给路径+关键行号，不说"我在 Z 文件中找到了..." |
| 遇错 | 直接说"X 不行因为 Y，建议 Z"，不说"很遗憾遇到了问题" |
| 提问 | 直接问，不说"我想确认一下..." |
| 完成 | 给结果+关键数字，不说"任务已完成" |
| TDD | 测试文件变更省略过程，只说覆盖率变化和阻断项（对齐 `tdd-check-output-convention`，通过静默/阻断显式列出） |

## 二、文档精简（零废话）

### 禁止清单

1. **禁止客套开头**："关于..."、"针对..."、"在当今..."、"随着..."等无信息量开头
2. **禁止重复上下文**：需求/上下文中已明确的事实，不重复解释（引用即可）
3. **禁止水字数填充词**："值得注意的是"、"不可否认"、"毫无疑问"、"显而易见"
4. **禁止冗余总结**：正文已说清的事，不需要"综上所述"段落再复述
5. **禁止过度铺垫**：背景/引言不超过全文 20%，超过则砍

### 格式约束

- **列表优先**：超过 3 个并列项，必须用列表，不写成长段落

### 文档类型专项

| 文档类型 | 精简标准 |
|---|---|
| 设计文档 | 问题→方案→权衡→决策，不要行业背景铺垫 |
| 评审报告 | 问题列表+严重程度，不要大段分析已知事实 |
| 日报 | 做了什么+结果，不写过程心理活动 |
| SPEC | 接口/行为/约束，不写"为什么需要这个功能"的鸡汤 |
| concerns.json | 结构化 P0/P1/P2 + file:line + 一句话描述，禁止纯叙述性评审产出（影响 `concern_stats` 统计） |

## 三、与其他 AI 规则的协调

### 与需求保真（`ai-behavior-constraints.md`）

| 冲突场景 | 处理方式 |
|---|---|
| 需求保真要求"领域复述" | 复述保留，但砍掉客套开头和冗余总结，只保留关键假设和待澄清 |
| 需求保真要求"假设清单" | 清单保留，但每条假设一句话，不写段落 |
| 需求保真要求"影响范围分析" | 分析保留，但结论前置，不写铺垫 |
| 需求保真 L1 复述 | 保留复述（这是验证理解，不是废话），但砍掉"根据您的需求..."等客套前缀 |

**原则**：需求保真的产出物保留，但用零废话规则压缩表达，不压缩信息。

### 与上下文压缩（`compact-instructions.md`）

本文件管"输出怎么写"，`compact-instructions.md` 管"压缩时保留什么"。子会话摘要格式以本文件为准（结构化三要素模板：文件路径 + 关键决策 + 测试结果）。

### 与任务完成留痕（`task-completion-gate.md`）

`warnings` 的软提示告知**不属于废话**——必须原样传达用户，不做润色或省略。状态移动后的 A/B/C 选项由用户选，AI 不预设答案。

### 兜底

当本文件与其他 `ai-rules/*.md` 冲突时：**强制结构化产出 > 零废话**（先保证信息不丢，再压缩表达）。
