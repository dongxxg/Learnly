# AI 行为约束 — 需求保真

## 需求保真（强制）

### 触发判断标准

满足以下**任一**条件时，开工前必须产出"领域复述 + 假设清单 + 待澄清"：

- **派生数据**：数据 A 依赖数据 B（摘要/明细、缓存/源数据、聚合/原始），变更 B 时 A 是否跟着变
- **多模块耦合**：改 A 模块行为，可能影响 B/C 模块（即使 B/C 不在本次改动范围）
- **外部依赖**：依赖 RPC、第三方服务、框架内部行为、并发/异步/生命周期等**不可本地验证**的因素
- **隐式约束**：业务规则、数据一致性、边界条件等**没写在需求里但显然存在**的约束

**豁免**：用户明确说"直接做"或"不用确认"时跳过，但需在 commit message 中注明"用户豁免确认"。

### 分级输出

按复杂度分级，避免简单需求也走全流程：


| 级别        | 触发条件                | 输出                 |
| --------- | ------------------- | ------------------ |
| **L1 轻量** | 单文件/单函数、逻辑自包含、无外部依赖 | 一句话复述 + 1 条假设      |
| **L2 标准** | 多模块/派生数据/外部依赖       | 领域复述 + 假设清单 + 待澄清  |
| **L3 深度** | 跨系统/数据迁移/架构变更       | L2 + 影响范围分析 + 回滚方案 |


### 输出格式（L2 标准）

```
## 领域复述
用一段话复述你对需求及其业务上下文的理解。

## 假设清单
- [ ] 假设 1：...（如果此假设不成立，我会观察到：...）
- [ ] 假设 2：...（如果此假设不成立，我会观察到：...）

## 待澄清
- 问题 1：...
- 问题 2：...
```

### 与工作流的关系


| 工作流                            | 处理方式                              |
| ------------------------------ | --------------------------------- |
| rd-auto pipeline（有 explore 阶段） | 不重复产出，explore 的 proposal 视为已满足本规则 |
| natural 模式（直接 Agent Developer） | 强制产出假设清单                          |
| hotfix/quick                   | 豁免（紧急修复不需要需求保真）                   |


### 规则

- 假设必须**可证伪**：每条假设附带"不成立时的观察现象"，禁止不可证伪的泛泛假设（如"假设服务可用"）
- 待澄清必须是**真实疑问**，禁止编问题凑数
- 用户确认后才开始实现，禁止跳过此步骤直接写代码
