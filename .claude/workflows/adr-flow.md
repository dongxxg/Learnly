# ADR 决策记录流程

> **版本**: v1.0
> **编制**: Architect / 主会话
> **生效日期**: 2026-04-15

## 概述

ADR（Architecture Decision Record，架构决策记录）是记录重大架构决策的标准化文档。本流程定义了ADR的创建、评审、审批和归档流程。

## ADR 适用场景

### 必须创建 ADR 的场景（单向门决策）

| 场景类别 | 具体内容 | 示例 |
|---------|----------|------|
| **数据层变更** | 数据库选型、更换、迁移 | MySQL → PostgreSQL |
| **元模型变更** | SDD L0 修改、元模型重大变更 | 本体核心概念调整 |
| **模型变更** | LLM 模型版本切换 | GPT-4 → Claude 3.5 |
| **Schema 变更** | 接口契约重大变更、数据结构变更 | API 字段类型变更 |
| **架构模式** | 架构风格切换、通信模式变更 | 单体 → 微服务 |
| **安全机制** | 认证授权机制变更 | Session → JWT |
| **性能关键** | 性能关键路径设计变更 | 缓存策略变更 |

### 可选创建 ADR 的场景

| 场景 | 说明 |
|------|------|
| 技术选型 | 有多个备选方案时的技术选型 |
| 设计权衡 | 需要记录利弊权衡的设计决策 |
| 团队分歧 | 需要记录辩论过程和裁决的决策 |

## ADR 创建流程

### 1. 触发条件

- Architect 识别到单向门决策
- 主会话 在质量门禁检查时发现需要ADR
- PM 明确要求创建 ADR

### 2. 创建步骤

```
┌─────────────────────────────────────────────────────────────────┐
│                     Architect 触发 ADR 创建                      │
└────────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  步骤1: 读取模板                                                │
│  - 读取 .harness/templates/adr-template.md                        │
│  - 理解各章节要求                                               │
└────────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  步骤2: 填写内容                                                │
│  - 元信息: 编号、状态、提出人、日期                              │
│  - 背景: 问题描述、业务驱动力、技术痛点                         │
│  - 决策: 一句话明确决策内容                                     │
│  - 理由与影响: 正面/负面影响、风险与缓解措施                    │
│  - 备选方案: 至少2个备选方案                                    │
│  - 实施计划: 关键步骤清单                                       │
│  - 辩论记录: 如有分歧，记录观点交锋                             │
└────────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  步骤3: 存放文件                                                │
│  - 路径: .harness/adr/ADR-{编号}-{标题}.md                       │
│  - 编号规则: AD-XXX（连续编号）                                 │
└────────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  步骤4: 交付 主会话                                          │
│  - 向 主会话 提交报告，包含 ADR 路径                         │
│  - 在架构文档中引用该 ADR                                       │
└─────────────────────────────────────────────────────────────────┘
```

### 3. 模板使用说明

**模板位置**: `.harness/templates/adr-template.md`

**必填章节**:
- 元信息
- 背景
- 决策
- 理由与影响
- 备选方案（至少2个）
- 实施计划

**可选章节**:
- 辩论记录（有分歧时填写）
- 评审记录（多人评审时填写）

## ADR 评审流程

### 评审触发

- Architect 完成后自动触发 主会话 初审
- PM 可主动要求评审
- 高风险 ADR 触发 Debate 对抗审计

### 评审检查项

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 格式完整性 | 使用模板，必填章节齐全 | 返回 Architect 补齐 |
| 决策清晰度 | 决策明确，无歧义 | 返回 Architect 修改 |
| 备选方案 | 至少2个备选方案，有明确取舍 | 返回 Architect 补充 |
| 风险识别 | 识别主要风险，有缓解措施 | 返回 Architect 完善 |
| ADR 编号 | 编号连续，无重复 | 主会话 分配新编号 |

### Debate 对抗审计（高风险 ADR）

以下情况触发 Debate：
- 跨模块重大变更
- 涉及安全关键路径
- 涉及性能关键路径
- PM 主动触发

## ADR 状态管理

| 状态 | 说明 | 转换条件 |
|------|------|----------|
| **已提议** | 初稿完成，待评审 | Architect 创建后 |
| **已接受** | 评审通过，成为决策红线 | 主会话/PM 批准 |
| **已废弃** | 不再适用，保留历史 | 新ADR替代或场景变化 |
| **已替代** | 被新ADR替代 | 新ADR标注"替代了 ADR-XXX" |
| **已拒绝** | 评审未通过 | Debate 裁决拒绝 |

## ADR 编号规则

### 编号格式

```
ADR-{编号}-{标题}
```

### 编号分配

- **全局连续**: 所有ADR共享编号空间
- **主会话 分配**: Architect 创建时向 主会话 申请编号
- **前缀约定**:
  - AD-XXX: 架构决策
  - TD-XXX: 技术决策
  - SD-XXX: 安全决策

### 示例

```
ADR-003-debate-adversarial-audit.md
ADR-004-llm-model-switching.md
ADR-005-multi-tenant-isolation.md
```

## 质量门禁

### Reviewer 评分卡检查（ADR 纳入 QG-REV-001 评分）

- [ ] 单向门决策必须有 ADR
- [ ] ADR 使用模板填写完整
- [ ] ADR 存放于正确路径
- [ ] ADR 编号连续无重复

### 返工规则

| 问题类型 | 返工目标 | 修复标准 |
|----------|----------|----------|
| ADR 缺失 | Architect | 补齐 ADR |
| 格式不完整 | Architect | 使用模板补全 |
| 决策不清晰 | Architect | 明确决策内容 |
| 备选方案不足 | Architect | 补充至少2个方案 |

## 注意事项

1. **ADR 是单向门决策**: 一旦接受，后续修改需要新 ADR 并声明 "替代了 ADR-XXX"
2. **禁止原地修改**: 已接受的 ADR 禁止直接修改
3. **模板强制使用**: 必须使用 `.harness/templates/adr-template.md` 模板
4. **编号由 主会话 分配**: Architect 不得自行分配编号
5. **PM 有一票否决权**: PM 可否决任何 ADR，要求返工
