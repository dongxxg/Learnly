# 测试指南

> Tester 专用的测试策略和规范

## 测试层级

### 1. 单元测试 (Unit Tests)

**目标：** 测试单个函数/类的行为

**原则：**
- 快速执行
- 独立运行
- 覆盖边界情况

**覆盖目标：**
- 核心业务逻辑：100%
- 辅助函数：>80%
- 工具函数：>60%

### 2. 集成测试 (Integration Tests)

**目标：** 测试模块间的交互

**重点：**
- 关键接口
- 数据流
- 外部依赖

**策略：**
- 测试主要交互路径
- 验证错误处理
- 检查事务一致性

### 3. 端到端测试 (E2E Tests)

**目标：** 测试完整用户场景

**场景：**
- 关键业务流程
- 多步骤操作
- 跨系统交互

**原则：**
- 保持稳定
- 减少依赖
- 易于调试

## LLM 测试策略

### 挑战

LLM 生成代码的测试需要特殊考虑：
- 行为可能不稳定
- 边界情况多
- 需要验证实际效果

### 策略

1. **基于规范的测试**
   - 从 SPEC 生成测试用例
   - 验证输出符合规范

2. **示例驱动测试**
   - 使用示例输入/输出
   - 验证类似场景

3. **属性测试**
   - 测试通用属性
   - 验证不变量

4. **对比测试**
   - 对比新旧实现
   - 验证行为一致性

## 测试红线

### 必须测试的情况

- 用户输入处理
- 权限检查
- 数据验证
- 错误处理
- 边界条件

### 禁止行为

❌ 跳过测试编写
❌ 测试形同虚设
❌ 只测试成功路径
❌ 忽视边界情况
❌ 硬编码测试数据

## 与 Developer 协作

### Developer Concerns 处理

当 Reviewer 提出 P0/P1 问题后：

1. **验证问题**
   - 重新运行相关测试
   - 确认问题真实存在

2. **验证修复**
   - 确保修复后测试通过
   - 检查没有引入新问题

3. **回归测试**
   - 运行相关测试集
   - 验证没有破坏现有功能

### 测试更新流程

当功能变更时：

1. 更新测试用例
2. 添加新测试
3. 移除过时测试
4. 更新覆盖率报告
