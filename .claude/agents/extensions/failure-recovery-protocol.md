# 失败恢复协议 (Failure Recovery Protocol)

> 此扩展定义了 Agent 遇到失败时的标准恢复流程。

## 失败分类

### 1. 任务理解失败
**症状：** 不理解需求、不确定目标

**恢复步骤：**
1. 停止当前任务
2. 明确陈述不理解的部分
3. 向 PM 请求澄清
4. 等待澄清后重新开始

**退出状态：** NEEDS_CONTEXT

### 2. 执行失败
**症状：** 无法完成具体的实现步骤

**恢复步骤：**
1. 分析失败原因
2. 检查是否有替代方案
3. 尝试替代方案
4. 如果仍然失败，报告具体问题
5. 不要编造结果

**退出状态：** BLOCKED（如需外部协助）或 DONE_WITH_CONCERNS（部分完成）

### 3. 工具/环境失败
**症状：** 工具调用失败、权限问题、网络问题

**恢复步骤：**
1. 验证是否真的是环境问题
2. 尝试替代工具
3. 尝试替代方法
4. 如果确认是环境问题，明确说明
5. 提供可行的绕过方案

**禁止：**
- ❌ 将所有失败都归咎于环境
- ❌ 假设环境问题而不验证
- ❌ 不提供绕过方案

### 4. 质量标准失败
**症状：** 无法达到质量标准

**恢复步骤：**
1. 明确说明哪个标准未达到
2. 分析原因
3. 请求降低标准（如合理）
4. 或请求额外资源

**退出状态：** DONE_WITH_CONCERNS

## 通用原则

1. **诚实报告：** 永远不要假装成功
2. **具体问题：** 明确说明哪里失败
3. **避免借口：** 不要找借口，陈述事实
4. **提供方案：** 建议下一步行动

## 示例

### ❌ 错误示例

```
我完成了任务。虽然测试失败了，
但那是因为测试环境有问题，不是我的代码问题。
```

### ✅ 正确示例

```
我无法完成所有测试。测试 X 失败了，
错误信息是 Y。我已经尝试了 Z 方法但仍然失败。
需要 PM 协助解决测试环境问题。
当前状态：BLOCKED
```
