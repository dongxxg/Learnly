# Reviewer 评分指南

> Reviewer 专用的评分和质量门禁详细说明

## 评分维度

### 1. 规范合规性 (Spec Compliance)

**检查点：**
- [ ] 是否符合 SPEC 要求
- [ ] 是否有遗漏功能
- [ ] 是否有额外功能（未记录）

**评分：**
- 完全符合：满分
- 轻微偏离：-5 分
- 严重偏离：-20 分

### 2. 代码质量 (Code Quality)

**检查点：**
- [ ] 命名是否清晰
- [ ] 结构是否合理
- [ ] 是否有重复代码
- [ ] 是否有过长函数
- [ ] 注释是否恰当

**评分：**
- 优秀：满分
- 良好：-5 分
- 需改进：-15 分

### 3. 测试覆盖 (Testing Coverage)

**检查点：**
- [ ] 核心功能是否有测试
- [ ] 边界情况是否有测试
- [ ] 错误处理是否有测试
- [ ] 覆盖率是否达标

**评分：**
- ≥80%：满分
- 60-79%：-10 分
- <60%：-20 分

### 4. 性能考虑 (Performance)

**检查点：**
- [ ] 是否有明显性能问题
- [ ] 是否有不必要的复杂度
- [ ] 是否考虑了大数据量

**评分：**
- 优秀：满分
- 有小问题：-5 分
- 有严重问题：-20 分

### 5. 安全性 (Security)

**检查点：**
- [ ] 输入是否验证
- [ ] 输出是否转义
- [ ] 权限是否检查
- [ ] 敏感数据是否保护

**评分：**
- 安全：满分
- 有小问题：-10 分
- 有严重问题：-30 分

### 6. 可维护性 (Maintainability)

**检查点：**
- [ ] 代码是否易于理解
- [ ] 模块化是否合理
- [ ] 依赖关系是否清晰

**评分：**
- 优秀：满分
- 良好：-5 分
- 需改进：-15 分

### 7. 文档质量 (Documentation)

**检查点：**
- [ ] 更新了相关文档
- [ ] 复杂逻辑有注释
- [ ] API 文档是否更新

**评分：**
- 完整：满分
- 部分缺失：-5 分
- 严重缺失：-15 分

## 质量门禁

### P0 问题（一票否决）

- 规范严重偏离
- 功能缺失
- 安全漏洞
- 测试完全不通过

### P1 问题（需修复）

- 代码质量问题
- 测试覆盖不足
- 文档缺失
- 性能问题

### P2 问题（建议改进）

- 命名风格
- 小优化
- 非关键注释

## 评分计算

```
总分 = (规范合规 + 代码质量 + 测试覆盖 + 性能考虑 +
       安全性 + 可维护性 + 文档质量) × 权重

权重：
- Architect: 0.25
- Reviewer: 0.40
- Tester: 0.35
```

## 输出格式

```json
{
  "scores": {
    "spec_compliance": 85,
    "code_quality": 90,
    "testing_coverage": 80,
    "performance": 95,
    "security": 100,
    "maintainability": 85,
    "documentation": 90
  },
  "weighted_score": 87.5,
  "issues": {
    "p0": [],
    "p1": ["测试覆盖率略低于标准"],
    "p2": ["部分变量命名可以更清晰"]
  },
  "recommendation": "pass"
}
```
