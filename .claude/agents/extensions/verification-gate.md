# 验证门 (Verification Gate)

> 此扩展定义了 Agent 完成任务前的最终验证标准。

## 触发时机

在报告 DONE 或 DONE_WITH_CONCERNS 之前，必须通过此验证门。

## 通用验证清单

### 1. 任务完成度

- [ ] 所有要求的功能都已实现
- [ ] 没有遗漏的需求
- [ ] 没有跳过的步骤

### 2. 质量标准

- [ ] 代码符合规范
- [ ] 测试覆盖率达标
- [ ] 没有明显的性能问题
- [ ] 没有安全问题

### 3. 文档和报告

- [ ] 更新了相关文档
- [ ] 提供了清晰的报告
- [ ] 记录了所有问题
- [ ] 提供了后续步骤建议

### 4. 诚实性

- [ ] 没有编造结果
- [ ] 没有隐藏问题
- [ ] 没有夸大完成度

## 角色特定验证

### Architect

- [ ] 设计文档完整
- [ ] 接口定义清晰
- [ ] 技术选型有依据
- [ ] ADR 已创建（如需要）

### Developer

- [ ] 所有测试通过
- [ ] 代码已自审
- [ ] 遵循 TDD 原则
- [ ] 没有待办事项

### Reviewer

- [ ] 所有评审点已覆盖
- [ ] 评分已给出
- [ ] P0 问题已列出
- [ ] concerns.json 已更新

### Tester

- [ ] 测试已执行
- [ ] 结果有证据
- [ ] 覆盖率已计算
- [ ] Bug 已报告

### Debate

- [ ] 双方论据已记录
- [ ] 评分已计算
- [ ] 裁决已给出
- [ ] 记录已保存

## 验证失败处理

如果任何验证项失败：

1. **明确说明：** 哪项验证失败
2. **解释原因：** 为什么失败
3. **提供方案：** 如何修复
4. **选择状态：**
   - 轻微问题：DONE_WITH_CONCERNS
   - 严重问题：BLOCKED
   - 需要重新执行：NEEDS_CONTEXT

## 示例

### ❌ 错误示例

```
我完成了所有工作。虽然有一个测试失败了，
但应该没问题，可以合并。
```

### ✅ 正确示例

```
验证检查：
- 功能完成度：✅
- 质量标准：⚠️ 一个测试失败
- 文档报告：✅
- 诚实性：✅

测试 X 失败，需要修复。
当前状态：DONE_WITH_CONCERNS
后续步骤：修复测试 X 后重新验证
```
