# ADR 创建规范

> Architect 专用的架构决策记录创建流程

## ADR 结构

### 标准格式

```markdown
# ADR-XXX: [标题]

## 状态
**提议中** | 已接受 | 已废弃 | 已替代

## 背景
为什么需要这个决策？什么问题触发了这个决策？

## 决策
我们决定什么？使用简短清晰的语言描述。

## 理由
为什么做这个决策？列出驱动因素、标准、原则。

## 后果
采用这个决策会有什么影响？
- 正面：好的方面
- 负面：不好的方面
- 风险：潜在风险

## 替代方案
考虑过哪些其他方案？为什么没有选择？

## 实施步骤
如何实施这个决策？

## 参考资料
相关文档、链接
```

## 创建时机

### 应该创建 ADR 的情况

- 技术选型：框架、库、工具的选择
- 架构变更：系统结构的重要改变
- 数据设计：重要的数据模型决策
- 接口设计：跨模块接口定义
- 性能策略：重要的性能相关决策

### 不需要创建 ADR 的情况

- 局部实现细节
- 临时解决方案
- 显而易见的选择

## 评审标准

### 质量检查

- [ ] 状态明确
- [ ] 背景清晰
- [ ] 决策具体
- [ ] 理由充分
- [ ] 后果完整
- [ ] 替代方案考虑

### 完整性检查

- [ ] 所有章节都有内容
- [ ] 没有模糊表述
- [ ] 没有待办事项

## 存储位置

`.harness/adr/ADR-XXX-[标题].md`

## 编号规则

- ADR-001 到 ADR-099：框架级决策
- ADR-100 到 ADR-999：项目级决策
