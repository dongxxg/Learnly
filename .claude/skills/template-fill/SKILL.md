## Overview

读取模板文件，引导用户填写内容，输出完整文档。三个模板：

- `templates/kanban_template.md` — 战役看板
- `templates/L0_spec_template.md` — L0 系统规格（系统/产品级设计）
- `templates/L1_spec_template.md` — L1 版本 SPEC（版本范围、Sprint 计划、交付清单）

---

## When to Use / Not Use

- **Use**：用户想基于模板生成看板、L0 系统规格或 L1 版本 SPEC 文档
- **Not Use**：GitLab 看板上传 → `daily-report-legacy`；完整 SPEC 流程（设计+评审+归档）→ `rd:propose`；自由探索需求 → `rd:explore`

## 路由

| 用户说 | 用哪个模板 |
| --------------------- | --------------------- |
| 看板 / kanban / 战役看板 | `templates/kanban_template.md` |
| L0 / 系统规格 / 系统设计 | `templates/L0_spec_template.md` |
| L1 / 版本SPEC / 版本规格 / 版本计划 / Sprint计划 | `templates/L1_spec_template.md` |

无法判断时直接问"生成看板、L0 系统规格，还是 L1 版本 SPEC？"

**L0 vs L1 区分**：L0 描述一个系统/产品的整体架构与设计基线；L1 在 L0 之上定义**特定版本**的范围、优先级、Sprint 计划与交付清单。先有 L0 才能写 L1，L1 必须引用 L0 作为基线。

## 执行流程

先问用户："有现成的文档吗，还是逐段聊？"

### 有现成文档

1. 用户贴文档内容或给文件路径 → 读取
2. 读取对应模板，从文档中提取信息填入
3. 填完后输出全文让用户确认或修改
4. 用户确认后写文件

### 逐段聊

1. 读模板，逐段展示当前段需要填什么（用模板中的注释说明每段意图）
2. 用户说内容，AI 填入
3. 可 skip（标记 `<!-- TODO -->`），可"回去改 XXX"
4. 全部填完后写文件

### 输出路径

| 模板 | 默认文件名 |
| --- | --------------------- |
| 看板 | `./{看板名}_kanban.md` |
| L0 | `./SPEC-L0-{系统缩写}.md` |
| L1 | `./SPEC-L1-{系统缩写}-v{版本号}.md` |

## Common Mistakes

| 错误 | 正确做法 |
|------|----------|
| 用户给了一个文档路径就直接输出 | 先读文档内容，理解后再按模板填入 |
| 模板有占位符但用户没提供就自己编 | 不确定的内容留 `{占位符}` 或标记 `<!-- TODO -->`，不要编造 |
| 输出前不检查 | 写文件前逐项确认无残留 `{占位符}` |
| 把模板当 SPEC 制品提交到 .harness/spec/ | 纯本地文件，不做 SPEC 生命周期管理 |
| L1 没有先确认 L0 基线就开写 | L1 的 §0 基线字段必须指向具体 L0 文档；缺 L0 时先提示用户补 L0，或显式标记为 `<!-- TODO: 补 L0 基线 -->` |
| L1 §3.1 驱动力描述写成空话 | 必须基于 L0 暴露的具体结构短板，每条 gap 在 §5.2 P0 必达中要有对应交付 |

## 注意事项

- **不要编造** — 用户没说的内容不要自己补，不确定就问
- **不要强推** — 用户说"跳过"就跳过，不催促
- **先读文档再填** — 有现成文档模式下，读完读懂再填入，不要机械复制
- **逐段确认** — 逐段聊模式下，填完一段展示一段，不要一次性全填完再让用户检查
- **预览随时可用** — 用户说"预览"立即输出当前进度
- **不推 GitLab、不创建 SPEC 制品** — 纯本地文件输出
- **L1 必须锚定 L0** — L1 不是独立文档，§0 基线字段 / §3.1 驱动力 / §4.1 红线 都依赖 L0 的现状描述；填 L1 时如发现 L0 缺失或过时，先提示用户更新 L0
