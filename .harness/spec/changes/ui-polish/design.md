# ui-polish 设计

## Context

探索阶段（2026-10-15）现状盘点结论：uni.scss 仅 6 token 但采用率 100%（19 个 .vue 全引用 `$learnly-*`）；一致性靠复制粘贴（阴影 `0 2rpx 12rpx rgba(0,0,0,0.05)` ×19 处/14 文件、硬编码灰 `#e5e7eb` ×36、字号 16 种无刻度）；图标体系混乱（汉字/emoji 混用）；动效为零；双端已有条件编译与 aspect-ratio 兜底先例。架构既定决策：无 UI 组件库（literacy design.md 明文），自绘路线。教学组件（hanzi-writer-board / letter-copybook / stroke-strip）的格线几何是与 hanzi-writer Positioner 数据空间及 gen-letter-data.mjs 三方同源的数学契约。

## Goals / Non-Goals

**Goals:**
- 一致性从"纪律产物"变为"体系产物"：token 覆盖色彩/字阶/间距/圆角/阴影/状态色
- 视觉方向 C 落地：清爽底 + 童趣点缀（品牌绿渐变 hero、小芽吉祥物、完成庆祝动效）
- 双端（H5 + mp-weixin）全量可用，功能行为零变化
- 三端截图比对回归通过，新增资产体积有预算约束

**Non-Goals:**
- 不引入 UI 组件库、不改任何功能逻辑/接口/数据结构
- 不做小程序分享图、骨架屏、空态流程、逐页导航栏主题（上线 checklist 另行处理）
- 不做深色模式（v1 不含，token 层预留 CSS 变量扩展点）
- 不重写教学组件渲染架构

## Decisions

### D1: 视觉方向 = C（清爽底+童趣点缀）

**选择**：现有清爽卡片风为底，童趣集中在三处——hero 渐变+吉祥物、完成庆祝动效、图标插画质感。

**替代方案**：
- A) 精致清爽（Duolingo 式打磨）——家长视角可信但儿童产品辨识度不足，"3 秒感受不到是给孩子做的"
- B) 童趣插画风（大插画+吉祥物贯穿）——插画资产产出不可持续（纯手搓 SVG 撑不起全插画路线），且家长观感有"幼稚"风险

**理由**：双受众平衡（家长付费看专业度、孩子使用要反馈感），且对手搓资产的需求量最小。

### D2: 令牌双轨交付 = SCSS 变量（编译期）+ CSS 变量（运行时，页面根 class 注入）

**选择**：uni.scss 保持唯一事实源；App.vue 全局注入 `:root`/page 级 CSS 变量与 SCSS 同值；新代码优先用 SCSS 变量，动效/需运行时能力处用 CSS 变量。

**替代方案**：
- A) 纯 CSS 变量——现有 57+ 处 `$learnly-*` 引用需全量改写，改动面无谓扩大
- B) 纯 SCSS 变量——mp 端 keyframes/条件样式无运行时能力，庆祝动效与后续主题扩展受限

**理由**：双轨成本≈0（同值两份，一个 sync 断言测试防漂移），兼容现有引用又给动效留运行时通道。mp-weixin 基础库 2.x 支持 CSS 变量，已有项目实践。

### D3: 组件路线 = 自绘共享件（LCard/LButton/LPageHeader）

**选择**：抽 3-5 个轻量共享组件到 `components/ui/`，内置 mp button 默认样式 reset。

**替代方案**：
- A) 引入 wot-design-uni / uv-ui——违背 literacy design.md"无 UI 库"既定决策；默认观感模板化；包体压力；canvas 教学页回归风险
- B) 不抽组件继续逐页手写——19 处阴影复制继续漂移，一致性仍是纪律产物

**理由**：与既定架构一致、零新依赖、包体影响≈0。

### D4: 图标与吉祥物 = 内联 SVG 组件双端分支

**选择**：图标统一为 SVG 线性风格 Vue 组件；H5 端内联 SVG，mp 端经 base64 data URL 走 `<image>`；吉祥物为单文件 SVG 组件，仅 hero/庆祝/空态三类场景出现。

**替代方案**：
- A) iconfont——mp 端需 base64 内嵌且单色限制，多色插画质感做不到
- B) PNG 切图——多分辨率维护成本、无法动态变色、包体大

**理由**：SVG 单源缩放无损、可 CSS 控色，与"纯手搓资产"决策配套；stroke-strip 已有 mp 端 SVG→canvas 指令式绘制先例可参考。

### D5: 动效 = 纯 CSS keyframes 三档（按压/转场/庆祝）

**选择**：按压反馈（scale 0.97 + 100ms）、页面转场（uni-app 原生转场配置级）、完成庆祝（撒花+星星，≤800ms，CSS animation 编排）。

**替代方案**：
- A) Lottie——新增依赖+包体+mp 端兼容三重风险，庆祝动效复杂度撑不起
- B) renderjs/canvas JS 动画——mp 端复杂度高，v1 动效全部可 CSS 表达

**理由**：CSS 动画是双端安全区（已有代码实践），零依赖零包体负担；`prefers-reduced-motion` H5 端尊重、mp 端不支持则忽略。

### D6: 迁移策略 = 分批渐进（令牌先行→共享件→逐页机械替换）

**选择**：每批 3-5 页，改完即截图比对再进下一批。顺序：首页/TabBar → 英语 → 数学 → 汉语/识字 → 古诗 → auth。

**替代方案**：
- A) 大爆炸一次全改——19 文件回归面爆炸，错位难定位
- B) 只改新页面不动旧页——页面气质继续分裂，达不到上线标准

**理由**：每批可独立验证/回滚（纯前端 git revert 即可），截图比对作为逐批门禁。

### D7: 字体 = 系统字体栈为基线 + 品牌字体 spike 后定夺

**选择**：v1 基线用现有系统栈（PingFang SC 等）；品牌圆润字体（候选：阿里妈妈方圆体/得意黑）做 `wx.loadFontFace` + `@font-face` 双路 spike，验证通过（域名白名单、加载闪烁可控、包体/CDN 方案成立）才全量引入，否则维持系统栈。

**替代方案**：
- A) 直接全量引入品牌字体——白名单申请、加载闪烁（FOUT）、体积三风险未验证就上，回退成本高
- B) 永久放弃品牌字体——儿童产品字形亲和力有价值，不值得直接放弃

**理由**：spike 成本半天级，结论驱动决策；失败路径（系统栈）本就是基线，零回滚成本。

### D8: 教学组件红线 = 几何百分比冻结 + 色值 token 化 + 快照守护

**选择**：田字格/四线三格 linear-gradient 的线位百分比原样保留，仅线色/背景色 token 化；`hanzi-writer-mp` canvas 配色常量同步 token 值；迁移前后对该 3 组件做渲染快照比对（H5 截图 diff）。

**替代方案**：
- A) 几何参数配置化重构——动数学契约，三端 canvas/SVG 字形错位风险，收益为零
- B) 教学组件完全不动——边框/阴影与全站气质脱节

**理由**：色值与几何分离是本变更内零风险可达的最大一致收益；快照守护让"没动几何"可验证。

## Risks / Trade-offs

- [mp 端 CSS 变量注入时机与兼容] → 双轨设计使 CSS 变量非必需路径；mp 真机/开发者工具逐批验证
- [SVG data URL 在 mp 端 image 的渲染差异] → 图标组件双端分支各自截图验收；异常时回退单色 PNG（体积预算内）
- [字阶/间距统一引发既有页行高溢出、换行] → 逐页迁移+截图比对门禁；字阶向最近档取齐而非强行归档
- [新增资产撑爆 2MB 主包] → 硬预算：图标集总量 ≤60KB、吉祥物 ≤30KB、动效纯 CSS 0 资产；构建产物核对入 tasks
- [庆祝动效在低端机掉帧] → 动效只动 transform/opacity 合成属性；粒子数上限约束（≤24）
- [token 改色后 pages.json 物理重复漂移] → sync 断言测试（读 pages.json 与 token 值比对）

## Migration Plan

1. 令牌层落地（旧 6 变量保持兼容，纯增量）
2. 共享件+资产入库（不被页面引用即无影响）
3. 逐页迁移 6 批，每批截图比对
4. 动效层叠加（独立 commit，可单独 revert）
5. 双端专项（字体 spike、TabBar PNG、体积核对、全量回归）

回滚策略：纯前端改动，按批 git revert；无数据/接口迁移。
